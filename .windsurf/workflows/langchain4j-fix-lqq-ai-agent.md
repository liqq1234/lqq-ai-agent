---
description: 使用 langchain4j-main 示例代码来分析和修复 lqq-ai-agent 项目的问题
---

1. 选择当前要解决的问题
   - 在 lqq-ai-agent 项目中，确定一个具体的报错或功能异常。
   - 收集最小复现信息：请求参数、期望结果、实际结果、异常栈。

2. 准备上下文并引用文件
   - 在对话中使用 @ 引用：
     - 出问题的业务文件，例如 lqq-ai-agent 中的某个类。
     - 你认为相关的 langchain4j 示例文件（在 langchain4j-main 中的 examples 或 integration-tests 等）。
   - 用一两句话描述：
     - 现在的实现做了什么
     - 希望它变成怎样

3. 让 Cascade 对比示例和业务代码
   - 在对话中明确提出需求，例如：
     - “参考这个 langchain4j 示例文件，检查我在 lqq-ai-agent 里的用法有没有错，指出不一致的地方。”
     - “按示例里的写法，帮我改造这段代码，并解释原因。”
   - 关注这些点的对比：
     - model 类型、构造方式、配置参数
     - prompt 结构、消息角色、变量传递
     - chain / agent 的组装方式
     - 工具调用、memory、retrieval 等用法

4. 生成并应用修改方案
   - 让 Cascade 给出针对 lqq-ai-agent 的具体修改方案：
     - 标明需要修改的类名、方法名、字段名
     - 指出要新增或调整的 import、配置项
     - 给出修改前后代码片段对比
   - 确认方案后：
     - 让 Cascade 使用 Write Mode 或代码编辑工具修改对应文件
     - 或者你手动按方案修改，保留关键差异点

5. 运行并验证结果
   - 在 lqq-ai-agent 中运行相关测试或启动程序：
     - 单元测试 / 集成测试
     - 本地启动服务后发起一次真实请求
   - 如果出现新的异常：
     - 把最新的异常栈贴到对话中
     - 继续使用本 workflow，从步骤 2 重新选择更贴近的 langchain4j 示例进行对比

6. 复盘并沉淀经验（可选）
   - 对于已经成功解决的问题：
     - 总结三点：问题现象、使用到的 langchain4j 示例文件、最终修复方式
   - 使用 /add-rule workflow：
     - 把这段总结加入全局规则
     - 方便后续遇到类似问题时快速复用解决思路
