## 🔴 错误 1：登录时 CORS 预检请求失败

### 问题描述
**时间**: 2025-11-22 21:04  
**错误信息**: `com.lqq.lqqaiagent.exception.BusinessException: 未登录`  
**触发场景**: 点击前端登录按钮时  
**堆栈关键信息**: `FrameworkServlet.doOptions` → 说明是 OPTIONS 预检请求被拦截

### 错误原因
1. **CORS 预检请求被拦截**: 浏览器发送 OPTIONS 预检请求，被 `UserContextInterceptor` 拦截
2. **拦截器强制校验登录**: 所有请求都要求用户已登录，包括 OPTIONS 请求
3. **Spring Security 未正确配置 CORS**: 导致预检请求无法通过

### 请求流程（错误）
```
浏览器 → OPTIONS 预检请求 → Spring Security → UserContextInterceptor
                                                    ↓
                                            检查登录状态（Session）
                                                    ↓
                                            抛出"未登录"异常 ❌
```

### 解决方案

#### 修复 1: 拦截器放行 OPTIONS 请求

**文件**: `lqq-common/src/main/java/com/lqq/lqqaiagent/config/interceptor/UserContextInterceptor.java`

```java
@Override
public boolean preHandle(HttpServletRequest request,
                         HttpServletResponse response,
                         Object handler) {

    // 放行 OPTIONS 请求（CORS 预检请求）
    if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
        return true;
    }

    // 从 Session 获取当前登录用户
    Object userObj = request.getSession().getAttribute(USER_LOGIN_STATE);
    ThrowUtils.throwIf(userObj == null, ErrorCode.NOT_LOGIN);
    if (userObj instanceof User user) {
        UserContext.setUser(user);
    }

    return true;
}
```

#### 修复 2: Spring Security CORS 配置

**文件**: `lqq-common/src/main/java/com/lqq/lqqaiagent/config/SecurityConfig.java`

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
            .csrf(csrf -> csrf.disable())
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))  // 启用 CORS
            .authorizeHttpRequests(auth -> auth.anyRequest().permitAll())
            .httpBasic(httpBasic -> httpBasic.disable())
            .sessionManagement(session -> session
                    .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
            );

    return http.build();
}

@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration configuration = new CorsConfiguration();
    configuration.setAllowedOriginPatterns(Arrays.asList("*"));
    configuration.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    configuration.setAllowedHeaders(Arrays.asList("*"));
    configuration.setExposedHeaders(Arrays.asList("*"));
    configuration.setAllowCredentials(true);  // 允许携带 Cookie
    configuration.setMaxAge(3600L);  // 预检请求缓存 1 小时

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", configuration);
    return source;
}
```

### 验证方法
```bash

curl -X OPTIONS http://localhost:8224/api/user/login \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: POST" \
  -v
```

## 🔴 错误 2：前端请求路径不匹配（404 错误）

### 问题描述
**时间**: 2025-11-22 21:20  
**错误信息**: `404 Not Found` for `http://localhost:8224/api/user/login`  
**触发场景**: 前端点击登录按钮时  
**浏览器错误**: `Failed to load resource: the server responded with a status of 404`

### 错误原因
1. **前端配置错误**: `.env.development` 配置为 `http://localhost:8224`，没有包含 `/api` 前缀
2. **后端配置**: `application.yml` 中配置了 `context-path: /api`
3. **路径不匹配**: 前端请求 `/user/login` → 实际访问 `http://localhost:8224/user/login` → 404

### 请求流程（错误）
```
前端: request.post('/user/login', ...)
      ↓
拼接: http://localhost:8224 + /user/login
      ↓
实际: http://localhost:8224/user/login ❌
期望: http://localhost:8224/api/user/login ✅
```

### 解决方案

**文件**: `lqq-ai-agent-frontend/.env.development`

```bash
# 修改前
VITE_API_BASE_URL=http://localhost:8224

# 修改后
VITE_API_BASE_URL=http://localhost:8224/api
```

### 验证方法
1. 修改后重启前端服务
2. 打开浏览器开发者工具
3. 点击登录，观察请求 URL：
   - ✅ 正确: `http://localhost:8224/api/user/login`
   - ❌ 错误: `http://localhost:8224/user/login`

### 注意事项
- 环境变量修改后**必须重启前端服务**才能生效
- Vite 不会自动热重载环境变量

## 🔴 错误 3：后端服务未包含 Controller（404 错误）

### 问题描述
**时间**: 2025-11-22 21:22  
**错误信息**: `404 Not Found` for `http://localhost:8224/api/user/login`  
**触发场景**: 前端访问登录接口  
**根本原因**: `lqq-bootstrap` 模块没有依赖 `lqq-chat` 模块

### 错误原因
1. **模块依赖缺失**: `lqq-bootstrap/pom.xml` 只依赖了 `lqq-common`，没有 `lqq-chat`
2. **Controller 未加载**: `UsersController` 在 `lqq-chat` 模块中，启动类扫描不到
3. **运行时缺少接口**: 虽然代码存在，但运行的应用中没有这些接口

### 项目结构
```
lqq-ai-agent/
├── lqq-bootstrap/     # 启动模块（运行入口）
│   └── pom.xml        # ❌ 缺少 lqq-chat 依赖
├── lqq-common/        # 公共模块（实体、Service、配置）
├── lqq-chat/          # 聊天模块（Controller、Service）
│   └── UsersController.java  # 登录接口在这里
```

### 解决方案

**文件**: `lqq-bootstrap/pom.xml`

```xml
<dependencies>
    <!-- 依赖公共模块 -->
    <dependency>
        <groupId>com.lqq</groupId>
        <artifactId>lqq-common</artifactId>
        <version>0.0.1-SNAPSHOT</version>
    </dependency>

    <!-- 依赖聊天模块，包含 Controller -->
    <dependency>
        <groupId>com.lqq</groupId>
        <artifactId>lqq-chat</artifactId>
        <version>0.0.1-SNAPSHOT</version>
    </dependency>
</dependencies>
```

### 重启步骤
1. **停止后端服务**: 在 IDE 中停止 `LqqAiAgentApplication`
2. **重新编译**: `mvn clean install -DskipTests`（可选）
3. **重新启动**: 启动 `LqqAiAgentApplication`
4. **验证**: 查看启动日志是否包含 `Mapped "{[/api/user/login],methods=[POST]}"`

### 验证方法
```bash
# 测试接口是否可用
curl -X POST http://localhost:8224/api/user/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"123456"}'
```

## 🔴 错误 4：聊天回复格式显示不正确

### 问题描述
**时间**: 2025-11-22 21:35  
**问题现象**: AI 回复显示为原始 JSON 对象，而不是回复内容  
**显示内容**: `{ "message": "你好！...", "timestamp": 1763818538270 }`  
**期望内容**: `你好！...`

### 错误原因
1. **前端直接显示整个响应对象**: `chatStore.updateLastMessage(response)`
2. **没有提取 data.message**: 应该使用 `response.data.message`
3. **后端返回格式**: `BaseResponse<Map<String, Object>>`，data 中包含 message 字段

### 后端响应格式
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "message": "AI 的回复内容",
    "timestamp": 1763818538270
  }
}
```

### 解决方案（已改为流式）

由于后续改为流式聊天，此问题已通过使用 SSE 接口解决。

**流式聊天的优势**：
- 逐字显示，体验更好
- 直接接收文本片段，无需解析 JSON
- 不会出现格式显示问题

## 🔴 错误 5：聊天功能非流式（一次性显示）

### 问题描述
**时间**: 2025-11-22 21:35  
**问题现象**: AI 回复一次性全部显示，没有打字机效果  
**触发场景**: 使用 `/chat/message` 普通接口  
**期望效果**: 逐字显示（流式输出）

### 错误原因
1. **使用了普通接口**: `/chat/message` 返回完整响应
2. **没有使用流式接口**: 应该使用 `/chat/stream` SSE 接口
3. **前端代码**: 使用了 `chatService.sendMessage()` 而不是 SSE

### 解决方案

#### 修复 1: 修改后端支持 GET 请求

**问题**: `EventSource` 只支持 GET 请求，但后端接口是 POST

**文件**: `lqq-chat/src/main/java/com/lqq/lqqaiagent/controller/ChatController.java`

```java
// 修改前
@PostMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamChat(@RequestBody Map<String, String> request) {
    String message = request.get("message");
    // ...
}

// 修改后
@RequestMapping(value = "/stream", method = {RequestMethod.GET, RequestMethod.POST}, 
                produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamChat(
        @RequestParam(value = "message", required = false) String messageParam,
        @RequestBody(required = false) Map<String, String> request) {
    // 优先使用 GET 参数，否则使用 POST body
    String message = messageParam != null ? messageParam : 
                    (request != null ? request.get("message") : null);
    // ...
}
```

#### 修复 2: 前端使用 SSE 连接

**文件**: `lqq-ai-agent-frontend/src/views/ChatInterface.vue`

```javascript
// 修改前（普通接口）
const response = await chatService.sendMessage(message)
chatStore.updateLastMessage(response)

// 修改后（流式接口）
import { connectSSE } from '@/api/index'

let fullResponse = ''

const eventSource = connectSSE(
  '/chat/stream',
  { message }, // GET 查询参数
  (data) => {
    if (data === '[DONE]') {
      console.log('✅ 流式聊天完成')
      chatStore.setLoading(false)
    } else {
      fullResponse += data
      chatStore.updateLastMessage(fullResponse) // 实时更新
    }
  },
  (error) => {
    console.error('❌ 流式聊天失败:', error)
    chatStore.updateLastMessage(`抱歉，发生了错误: 连接失败`)
  }
)
```

### 重启步骤
1. **停止后端服务**
2. **重新启动后端**（加载修改后的 ChatController）
3. **前端自动热重载**（无需重启）

### 验证方法

## 🔴 错误 6：AI 回复 Markdown 格式显示混乱

### 问题描述
**时间**: 2025-11-22 21:47  
**问题现象**: AI 回复的 Markdown 格式没有正确渲染  
**显示内容**:
```
1.**基础知识**：
 -**理解概念**：首先需要...
```

**期望内容**:
1. **基础知识**：
   - **理解概念**：首先需要...

### 错误原因
1. **前端未渲染 Markdown**: 直接显示原始文本
2. **缺少 Markdown 解析器**: 没有安装 markdown-it
3. **缺少代码高亮**: 没有安装 highlight.js
4. **缺少样式**: 没有 Markdown 相关 CSS

### AI 回复的 Markdown 示例
```markdown
1. **基础知识**：
   - **理解概念**：首先需要...
   - **了解基本语法**：学习如何...

2. **安装环境**：
   - 下载并安装 JDK
   - 选择一个 IDE

\`\`\`java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
\`\`\`
```

### 解决方案

#### 步骤 1: 安装依赖

```bash
npm install markdown-it highlight.js
```

#### 步骤 2: 修改 ChatBubble 组件

**文件**: `src/components/ChatBubble.vue`

```javascript
import { computed } from 'vue'
import MarkdownIt from 'markdown-it'
import hljs from 'highlight.js'

// 配置 Markdown 解析器
const md = new MarkdownIt({
  html: true,
  linkify: true,
  typographer: true,
  breaks: true,
  highlight: function (str, lang) {
    if (lang && hljs.getLanguage(lang)) {
      try {
        return '<pre class="hljs"><code>' +
               hljs.highlight(str, { language: lang, ignoreIllegals: true }).value +
               '</code></pre>'
      } catch (err) {
        console.error('代码高亮失败:', err)
      }
    }
    return '<pre class="hljs"><code>' + md.utils.escapeHtml(str) + '</code></pre>'
  }
})

// 渲染 Markdown
const renderedContent = computed(() => {
  if (!props.content) return ''
  
  if (props.from === 'ai') {
    return md.render(props.content)  // AI 消息渲染 Markdown
  }
  
  return props.content.replace(/\n/g, '<br>')  // 用户消息纯文本
})
```

**模板修改**:
```vue
<!-- 使用 v-html 渲染 -->
<div class="message-text" v-html="renderedContent"></div>
```

**文件**: `src/main.js`

## 🎓 经验总结

### 1. CORS 问题排查思路
- 看到 `OPTIONS` 请求报错 → 检查拦截器
- CORS 错误 → 检查 Spring Security 配置
- 预检缓存 → 设置 `maxAge` 减少请求

### 2. 404 问题排查思路
- 检查前端请求 URL
- 检查后端 context-path
- 检查 Controller 是否被扫描
- 检查模块依赖

### 3. 流式聊天关键点
- `EventSource` 只支持 GET 请求
- 后端接口需要同时支持 GET 和 POST
- SSE 返回格式：`data: xxx\n\n`
- 结束标记：`[DONE]`

### 4. Markdown 渲染注意事项
- 使用 `v-html` 需要注意 XSS 安全
- AI 消息渲染 Markdown，用户消息纯文本
- 代码高亮需要指定语言
- 使用 `:deep()` 选择器修改嵌套样式
