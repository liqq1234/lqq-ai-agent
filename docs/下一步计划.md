## 3. 推荐的「下一步开发路线」（按优先级）

### 阶段 1：先把“多会话聊天 + 会话持久化”补上

目标：从现在的「单次 `/agent/chat` 文本问答」，升级到**有会话列表 + 历史记录**的体验。

- **3.1 设计会话相关表和实体（在 [lqq-common](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-common:0:0-0:0)）**
  - 表（可以参考 AIDeepin 的 `docs/create.sql`）：
    - `conversation`：会话表（id、userId、appId、title、lastMessage、createTime、updateTime…）
    - `conversation_message`：消息表（convId、role、content、tokens、createTime…）
  - 对应：
    - `model.entity.Conversation`、`ConversationMessage`
    - Mapper + Service（`ConversationService`、`ConversationMessageService`）

- **3.2 在 [lqq-chat](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-chat:0:0-0:0) 增加会话接口**
  - 新建类似 `ConversationController`，提供：
    - 创建会话：`POST /conversation/create`
    - 获取我的会话列表：`GET /conversation/list/my`
    - 获取会话详情 + 消息列表：`GET /conversation/get`
    - 发送消息并得到回复：`POST /conversation/chat`
  - 内部调用 `UniversalAssistant` 时，传入：
    - 当前 App 的 `initPrompt`
    - 该会话的历史消息（做 multi-turn 聊天）

- **3.3 打通你 Agent 描述里提到的“记忆工具”**
  - [AgentController.getTools()](cci:1://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-chat/src/main/java/com/lqq/lqqaiagent/controller/AgentController.java:78:4-111:5) 里已经写了 `saveConversation / getConversationHistory` 等说明，但底层还没对应实现。
  - 在 [lqq-common](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-common:0:0-0:0) 实现一个 `ConversationMemoryService`：
    - `saveConversation(convId, msg)`、`listMessages(convId)`、`clear(convId)`、`getStats(userId)` 等。
  - 让 `UniversalAssistant` 或你的工具函数在生成回复后自动写入 `conversation_message`。

> 阶段 1 做完，你就有：  
> 登录 → 创建应用 → 选择应用 → 创建会话 → 连续对话（有历史、有会话列表）。

### 阶段 2：做一版「简化知识库 RAG」

目标：从“纯模型对话”升级到“结合文档的问答”。

- **2.1 数据结构（在 [lqq-common](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-common:0:0-0:0)）**
  - 知识库：`kb`（id、name、desc、ownerId…）
  - 文档：`kb_item`（kbId、title、content/rawPath…）
  - 向量：`kb_item_embedding`（itemId、embedding 向量 or 向量存储引用）
- **2.2 技术选型**
  - 你当前 [lqq-common](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-common:0:0-0:0) pom 里还没有 pgvector/neo4j 的依赖。
  - 可以先选一个**最简单可落地的**方案：
    - MySQL + LangChain4j 内存向量库（小规模测试）
    - 或引入 `langchain4j-pgvector`，用 Postgres + pgvector（更接近原项目）。
- **2.3 接口（在 [lqq-chat](cci:7://file:///c:/Users/LQQ/Workspace/IDEASpace/lqq-ai-agent/lqq-chat:0:0-0:0)）**
  - `KnowledgeBaseController`（用户侧）：
    - 创建知识库、上传文档（文本 / markdown 为主）、触发向量化、按 kbId 检索并问答。
  - 聊天时，结合：
    - `conversation` + 选中的知识库 → 先检索 topN 片段 → 拼上下文给 `UniversalAssistant`。
